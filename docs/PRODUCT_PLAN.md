# PakScope（包览）—— Linux 软件资产管理器

> 产品功能设计 / PRD v0.1（2026-10-12）  
> Slogan：装了什么，一眼看清。  
> 定位：优先为 Ubuntu / GNOME 用户提供轻量、直观、可审计的已安装软件清单、来源追踪、安装文件查询与安全卸载体验。  
> 项目名称为暂定名；公开发布前检查 GitHub 命名和商标冲突。

## 1. 解决的问题与边界

用户常通过 apt、安装 .deb、Snap、Flatpak、AppImage、手动解压、安装脚本、Conda/pip 等方式安装软件，久而久之不知道“装了什么、从哪来、放在哪、怎么卸载”。

PakScope 是**软件资产管理器**，不是软件商店，也不尝试取代 apt、snapd、flatpak。只读识别应优先于安装/删除操作。

**必须诚实呈现未知信息**：例如某个 APT 包原本是否通过双击 .deb 安装、真实首次安装日期、运行中的所有数据目录，系统未必能可靠恢复。标记“未知”而不是编造。

## 2. 目标用户

- 使用 Ubuntu 24.04/26.04 GNOME 的桌面用户；优先中文和英文。
- 经常从 GitHub Release 下载 .deb、AppImage 的用户。
- 需要判断系统磁盘占用、重复安装和卸载风险的开发者。

## 3. 命名与视觉方向

- 中文名：**包览**；英文名：**PakScope**；仓库暂定：`pakscope`；启动命令：`pakscope`。
- 品牌语言：友好、透明、精确、克制。图标构思为放大镜与四格应用图标的组合。
- GTK4 + libadwaita 原生圆角风格，默认跟随系统明暗主题，可选深色/浅色；后续可加简约点缀色。
- 左侧导航、中央应用列表、右侧详情抽屉；小窗口时详情切换为单独页面。
- 默认仅显示“可识别的用户应用”，底层软件包在专家模式中查看。

## 4. 信息架构

**首页**：已发现的桌面应用数、来源类别、需关注项（不是安全恐吓）、快速搜索、最近发现软件。

**已安装应用**：软件图标、友好名称、版本、来源、安装范围、体积类型、安装状态；按来源/类别/大小/更新时间筛选，模糊搜索，批量导出。

**安装位置**：安装文件/入口程序/快捷方式/用户数据/缓存以不同类型分组，附“打开所在目录”和“复制路径”。对于 APT 可以列举 dpkg 跟踪的文件；对于 AppImage 显示本体和 .desktop 入口；对无法确定路径明确提示。

**存储空间**：区分包管理器报告的安装体积、实际文件大小、专属用户数据、共享依赖。避免对共享文件重复计数；清理空间一律呈现为估算值。

**卸载中心**：预览删除的包及依赖、受影响应用、是否涉及系统关键组件、额外数据的单独选择项；必须二次确认才开始执行。展示官方包管理器产生的结果，不直接递归删目录。

**系统组件（专家模式）**：APT 所有已安装包、自动/手动标记、依赖信息、架构、包版本；默认只读，对 essential/protected、桌面核心及关键依赖禁用直接卸载。

**历史记录**：保存 PakScope 自己发起的操作日志（不假装能完整恢复系统所有历史）；可从可用的本地包管理器历史进行补充，注明不完整性。

**设置**：语言、主题、AppImage 扫描目录、隐私/日志、缓存刷新、显示专家模式、导出路径。

## 5. 统一应用模型

一条 `Application` 是面向用户的应用记录，可映射到多个 `InstallInstance`（如同一软件的 APT 与 Flatpak 版本）。不能把所有包和所有 .desktop 启动器强行一对一。

```text
Application
  display_name, icon, categories, desktop_entry_ids[]
  install_instances[]

InstallInstance
  id, backend(apt|snap|flatpak|appimage|manual|unknown)
  package_id, version, arch, scope(system|user)
  confidence(high|medium|low), source_evidence[]
  executables[], desktop_files[], tracked_files[]
  size{value,metric,provenance}, update_available?
  removal_capability(none|supported|protected)
```

**原则**：所有来源和安装路径需有证据和置信度；相同应用不同安装渠道保留各自记录；识别不确定时仅展示，不允许自动卸载。

## 6. 识别后端与权限

| 后端 | v0.1 检测 | v0.1 卸载 | 说明 |
|---|---|---|---|
| APT / dpkg | 是 | 是（安全白名单） | `dpkg-query`、`apt-mark`、APT 仿真规划，映射 AppStream 与 .desktop |
| Snap | 是 | 是 | 查询 snapd / snap 命令，展示数据与快照影响 |
| Flatpak | 是 | 是 | 系统级和用户级分开记录，应用与运行时区分 |
| AppImage | 是（用户可选目录） | 有条件 | 只管理确认过的文件；默认先移入回收站；图标/入口可清理 |
| 手动安装/源码编译 | 初步发现 | 否 | 通过 .desktop/路径识别并标注未知来源，不推断安全卸载 |
| pip / pipx / Conda | 逐步支持 | 首版否 | 环境级管理，避免误删系统 Python 或共享依赖 |
| .run / shell installer | 仅线索显示 | 否 | 无统一可靠卸载标准 |

普通权限即可读取绝大多数包数据库。APT 系统修改需要 Polkit 按需授权；授权助手应有明确受限 API，不通过 `sh -c` 执行任意拼接命令，也不启动常驻 root 守护进程。

## 7. 安全卸载标准

1. 删除前调用相应包管理器获取变更计划（APT 使用 simulation），展示确切影响；不允许只凭包名猜测依赖。
2. `Essential`、`Protected`、操作系统基础及关键桌面包（政策定义）默认不可在 UI 中卸载。遇到复杂连锁删除则拒绝并建议使用系统工具。
3. 对普通 APT 包，区分“卸载软件”和“清除系统级配置”；`autoremove` 另列候选，绝不作为默认动作。
4. 用户主目录的配置、缓存、工作数据默认**保留**，只能在核验归属后由用户独立选择清理。
5. 禁止盲目删除 `/usr`、`/opt`、`~/.config` 等共享或宽泛目录；禁止未经确认的递归清理。
6. 出现权限取消、APT 锁冲突、网络错误、事务失败时展示真实错误和恢复建议。
7. 操作日志不可含秘密令牌；需要删除前计划快照。日志不是回滚保障，不能虚假承诺任意卸载都可撤销。

## 8. 优先级与版本计划

### v0.1 MVP —— 安全盘点
- 原生 GTK4/libadwaita UI，简体中文/英文、暗色跟随系统。
- APT、Snap、Flatpak、已知 AppImage 目录的只读聚合。
- 搜索/筛选/排序、快捷方式/安装位置、证据与来源详情。
- APT 手动/自动安装识别，区分应用与包。
- 导出 JSON/CSV，生成诊断报告（可遮蔽用户名与路径）。
- 无 root 常驻服务；不在首版默认开放删除功能。

### v0.2 —— 可控卸载
- APT、Snap、Flatpak 的安全卸载、进度和日志。
- 模拟删除预览、系统保护、Polkit 按需授权。
- AppImage 专属文件移入回收站与 .desktop 项清理。
- 单独可选的配置清理和空间预估（只对可明确归属的项）。

### v0.3 —— 高级发现
- 手动软件与未知来源线索检测；自定义扫描目录与忽略规则。
- 应用重复安装提示、包文件清单、异常快捷方式检测。
- 软件历史和空间占用分析（带来源与不确定性说明）。

### v1.0 —— 稳定发布
- 完善辅助技术可访问性、键盘快捷键、繁体中文/其他语言。
- 系统级集成测试、升级兼容、Debian/Ubuntu 多版本支持。
- 发布 GitHub Release：优先 amd64 `.deb`，可选 arm64 / AppImage。
- 完整 README、截图、开发者贡献指南、安全政策和变更日志。

## 9. 工程方案

**建议：Rust + GTK4 + libadwaita。**

```
ui/                      # GTK 界面、状态与翻译
core/model/              # 标准化应用与安装实例
core/discovery/          # 发现器、桌面条目映射
backends/apt/
backends/snap/
backends/flatpak/
backends/appimage/
core/safety/             # 改动计划、系统保护
helper/                  # 按需提权的窄权限助手（v0.2）
tests/fixtures/          # 隔离样本与假包管理器输出
packaging/debian/
.github/workflows/
```

选择系统 GTK/libadwaita 动态依赖，不自带 Chromium/Electron 或 Python 运行时。构建可用 `cargo build --release`，发布时使用 strip、LTO 等体积优化。最终大小需 CI 实测，不能提前承诺固定数值。

缓存仅存提取的元数据；不用递归读取整块文件系统作为默认启动动作。耗时扫描异步执行，支持取消、增量刷新与超时。

## 10. 用户体验与交互准则

- 首页显示面向普通人的“应用”，默认不展示上千个系统库。
- 每个应用拥有 3 个层次：概览 → 安装位置 → 技术详情。
- 每个体积数字必须有说明：包声明占用、实际单文件大小或估算归因。
- 查询失败显示部分结果与错误细节，不因一个后端不可用就导致空白。
- 列表筛选实时响应；长列表采用虚拟化，不在 UI 线程执行包扫描。
- 保持 GNOME 风格，图标来源本地；不依赖联网才能显示已安装应用。

## 11. 测试与验收

必须覆盖：
- Ubuntu 26.04 GNOME 50、Wayland 与 X11，深浅色、普通及高 DPI、横竖屏窗口尺寸。
- 混合 APT/Snap/Flatpak/AppImage 同名应用、桌面入口缺失、包管理器不可用、多架构包。
- 未授权运行、取消 Polkit、APT 被占用、卸载模拟产生关键包连锁删除。
- 系统包保护策略、未知来源不可删除、符号链接与越界路径的保护。
- 软件列表可与 `dpkg-query`/`snap list`/`flatpak list` 对照；未知信息不显示为确定事实。
- 首版完成后量测 `.deb` 大小、安装后增量占用、启动时间、内存、首轮扫描时延。

## 12. 明确不做（初期）

- 完整 App Store / 应用市场与源管理。
- 自动清理一切残留、自动删除用户数据。
- 自动卸载 pip/Conda 系统环境或任意 shell 安装器。
- “一键加速系统”“智能修复所有问题”等高风险功能。
- 遥测、广告、强制登录、后台常驻服务。

## 13. 第一阶段建议工单

1. 建仓：MIT 或 GPL-3.0 等许可证选择、README、贡献规范、CI。
2. 构建空 GTK4/libadwaita 应用骨架（导航、搜索、详情、中文翻译）。
3. 实现标准化模型与 APT 后端的只读枚举及关键包保护标识。
4. 加入 Snap/Flatpak 只读后端，处理异常/缺失命令。
5. 通过 `.desktop` / AppStream 归一化图标与名称、关联启动器。
6. 实现 AppImage 用户授权目录扫描和可信文件证据。
7. 增加导出、错误日志、安全测试和 .deb 打包；在全新虚拟机或容器中验证。
8. 发布 `v0.1.0`（只读版本）后，再启动卸载功能开发。
